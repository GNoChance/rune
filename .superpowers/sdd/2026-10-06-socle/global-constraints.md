## Global Constraints

Chaque ligne s'applique à toutes les tâches ; une décision qui tranche un point laissé ouvert par la spec est marquée **[décision plan]**.

- **Poste et outils** : Windows 11, Node ≥ 24.7 (`engines`, `.node-version` = `24`), pnpm 10 (`packageManager: pnpm@10.x`). Pas de Docker ni de Python en local. Tout test hors `infra` tourne sous Windows dans un seul processus Node.
- **Versions** (figées dans le lockfile) : celles du Tech Stack ; pas d'`@anthropic-ai/sdk` dans le socle.
- **Résolution TS [décision plan]** : `module: "preserve"`, `moduleResolution: "bundler"`, imports relatifs sans extension, `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `noEmit`. Les paquets internes exportent `./src/index.ts` ; le serveur tourne sous `tsx` en dev et E2E, en bundle esbuild `server.mjs` en production.
- **Paquets** : contracts (constantes, schémas Zod et fabriques triviales, sans logique métier), domain (TS pur : date et aléa passés en paramètres), server, web. Dépendances autorisées : domain → contracts ; server → contracts, domain ; web → contracts, domain ; web (dev) → server pour `@appsport/server/testing`.
- **Commandes** : `pnpm lint` (biome check), `pnpm typecheck`, `pnpm test` (vitest run), `pnpm --filter @appsport/<pkg> test <motif>`, `pnpm --filter @appsport/web test:e2e <spec>` (sans `--` : pnpm 10 le transmet et Vitest ne filtrerait plus), `pnpm test:infra` (bats sur `infra/host/test`), lancé depuis Git Bash avec `bats` (devDependency, `pnpm exec bats`) et `jq` (`winget install jqlang.jq`) ; le job CI `infra` fait foi ; shellcheck et contrat d'image en CI seulement ; une étape vérifiable seulement en CI ou sur l'hôte le dit, avec la sortie CI attendue.
- **Langues** : identifiants, tables, colonnes et codes d'erreur en anglais ; interface, messages CLI et documentation en français ; commits conventionnels en français (`feat(auth): …`), scopes `socle`, `db`, `auth`, `admin`, `profil`, `salles`, `privacy`, `synchro`, `web`, `pwa`, `infra`, `ops`, `docs`, `ci`.
- **Unités** : charges en grammes entiers (`*G`, `*_g`) ; dates civiles `YYYY-MM-DD`, horodatages ISO 8601 UTC ; date civile et âge à l'heure de `Europe/Paris`.
- **SQLite** : `node:sqlite`, `journal_mode=WAL`, `synchronous=FULL`, `foreign_keys=ON`, `busy_timeout=5000`, tables `STRICT` ; booléen `INTEGER CHECK (x IN (0,1))`, JSON `TEXT CHECK (json_valid(x))`, énumérations `TEXT CHECK (x IN (...))` ; Kysely avec `CamelCasePlugin`.
- **Identifiants** : UUIDv7 en TEXT (client pour J, serveur sinon) ; `id = owner_id` pour `training_profile` et `health_screening` ; `gym_equipment.id = gym_id || ':' || equipment_code` ; `home_equipment.id = place_id || ':' || equipment_code`. Le serveur valide le format UUIDv7 sans ordonner selon son horodatage.
- **Colonnes +SYNC** : `owner_id`, `rev` (`server_meta.sync_counter`, incrémenté à chaque écriture), `created_at`, `updated_at` (heure serveur), `updated_by`, `deleted_at` ; index `(rev)` et `(owner_id, rev)` ; `owner_id` vient toujours de la session.
- **Ajouts au modèle [décision plan]** : (1) `server_meta.tombstone_purge_rev INTEGER NOT NULL DEFAULT 0` (410 `watermark_expired`, R-SYN-23) ; (2) contenu de `health_screening` et `limitation` nullable avec `CHECK (deleted_at IS NOT NULL OR <contenu NOT NULL>)` (tombstone sans contenu, R-SYN-9, P-CST-3) ; (3) `training_profile.goal/experience/days_per_week/session_minutes` nullables avant la fin de l'onboarding ; (4) `user.onboarding_step` ∈ `ONBOARDING_STEPS` ou NULL (dernier écran validé) ; (5) `session.must_change_password` booléen (admin connecté avec moins de 14 caractères, R-MDP-1) ; (6) `server_meta.epoch_started_at TEXT NOT NULL`, début de l'époque courante, posé par `init` (`initServerMeta`) et par chaque `rotateServerEpoch` (renvoi du retrait de consentement, R-SYN-28).
- **Registre** : `entityRules` couvre les 18 tables et toutes leurs colonnes ; un test échoue si une table ou colonne de `sqlite_schema` manque, ou si une table C1 à C3 liée à un utilisateur n'est pas exportée ou pas supprimée avec le compte (`onUserDelete` ∈ {`cascade`, `anonymize`}) ; exception : session : anonymize, non exportée, R-EXP-2.
- **Catégories** : C0 interne, C1 personnel, C2 santé (consentement `health` exigé), C3 sensible (brique 4). Les `*_hash` sont des `secretColumns` : jamais exportés, synchronisés, journalisés ni renvoyés.
- **Format d'erreur API [décision plan]** : `{ "error": <ApiErrorCode>, ...extra }`, par exemple `410 {"error":"account_deleted"}`, `426 {"error":"protocol_unsupported","serverProtocol":1,"minProtocol":1}` ; le client agit sur `error`, jamais sur le seul statut.
- **Admin et données des autres** : toute lecture C1 à C3 est filtrée par l'utilisateur de session ; la ressource C1 à C3 d'un autre donne `404`, jamais `403` (P-ADM-2) ; aucune route `/api/admin/*` ne renvoie de champ C1 à C3.
- **En-têtes HTTP** (toutes réponses) : `Strict-Transport-Security: max-age=31536000` ; `Content-Security-Policy: default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'` ; `Referrer-Policy: no-referrer` ; `X-Content-Type-Options: nosniff` ; `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()` ; `X-Appsport-Epoch` (`EPOCH_HEADER`) sur chaque réponse `/api/*`. Aucun script en ligne, aucune ressource tierce (P-LOG-4).
- **CSRF** : POST, PUT, PATCH, DELETE exigent `Origin` = `APP_ORIGIN` (`403 origin_mismatch`) ; POST, PUT, PATCH exigent `Content-Type: application/json` (`415 unsupported_media_type`) ; le client envoie `{}` à défaut de corps ; `Tailscale-User-*` ignorés.
- **Cookie de session** : `__Host-session=<base64url 32 octets>; HttpOnly; Secure; SameSite=Lax; Path=/` sans `Domain` sur une origine `https://` ; **[décision plan]** `dev-session` sans `Secure` sur `http://localhost:*` ; seule l'empreinte SHA-256 est stockée ; inactivité 90 j, durée absolue 365 j.
- **Comptes** : `MIN_AGE` 16 ; invitation 7 j, amorçage 24 h, réinitialisation 24 h ; code Crockford de 16 caractères (80 bits) affiché `XXXX-XXXX-XXXX-XXXX`, empreinte SHA-256, saisie tolérante (casse, espaces, tirets, I/L → 1, O → 0) ; note ≤ 60 ; pseudo 3 à 24 caractères contrôlés et stockés en NFC (lettres de l'écriture latine, accents admis, chiffres, `.`, `_`, `-`), clé NFKC puis minuscules, réservés `admin`, `appsport`, `systeme` ; mot de passe 12 à 128 points de code après NFC, 14 pour un admin ; Argon2id m = 19456 Kio, t = 2, p = 1, sel 16 octets, PHC.
- **Limitation des tentatives** (en mémoire, `LOGIN_LIMITS`) : par pseudo normalisé, attente de 1 min dès le 5e échec consécutif, doublée à chaque échec, 15 min au plus ; 10e échec sur une heure glissante → 1 h ; par IP 30 échecs par heure ; toute ressaisie du mot de passe (P-AUT-5) passe par ce limiteur (`verifyUserPassword`) ; vérification de codes 20 essais par heure et par IP (invitation : `check` et `accept` ; réinitialisation : `reset/check` et `reset` ; renvoi du retrait d'accord santé : `replay-withdraw`, limiteur propre).
- **Synchro** : `SYNC_PROTOCOL` = `MIN_PROTOCOL` = 1, en-tête `X-Appsport-Protocol` (`PROTOCOL_HEADER`) ; `SYNC_PUSH_MAX` 200 ; `SYNC_PULL_LIMIT` 500 ; `TOMBSTONE_TTL_DAYS` 90 ; `applied_op` purgée à 12 mois ; `EPOCH_RESEND_DAYS` 60 ; `SYNC_TIMEOUT_MS` 4000 ; reprises de 2 s à 5 min ; synchro 2 s après une série validée, toutes les 60 s quand l'outbox n'est pas vide et l'appli visible, vidage limité à 4 s avant le coach ; watermark opaque `<server_epoch>:<rev>`. L'état connecté ne vient jamais de `navigator.onLine`.
- **Classes de synchro** : J (outbox ; au socle seulement `sync_rejection`, dont le client n'écrit que `dismissed_at`), D (rien au socle), E (API en ligne ; hors ligne « Nécessite le réseau »), C (catalogue par ETag), H (jamais dans Dexie).
- **Prêt hors ligne** : vert si et seulement si la coquille du build courant est en précache, le catalogue local correspond à la dernière `catalog_version` connue, les illustrations référencées sont en cache et un pull a réussi il y a moins de 24 h.
- **PWA** : caches `shell-<buildHash>` et `illustrations-v1` ; `index.html` et `sw.js` en `no-cache` ; fichiers hachés en `public, max-age=31536000, immutable` ; mode prompt ; navigation servie depuis `shell-<buildHash>` (cache d'abord, réseau seulement si `index.html` manque, ADR 0001) ; un SW en attente dont `localDbVersion` est inférieur à celui de la page n'est jamais activé ; recherche de mise à jour au lancement, au premier plan et toutes les 60 min ; jamais de bandeau pendant une séance (`activeSessionId`) ni pendant l'onboarding ; IndexedDB jamais effacé par une mise à jour ni par l'interrupteur d'urgence (`SW_KILL_SWITCH=1`).
- **Configuration serveur** (variables d'environnement seulement) : `APP_ORIGIN` (obligatoire), `APP_VERSION` (`dev`), `PORT` (3000), `HOST` (`0.0.0.0`), `APPSPORT_DATA_DIR` (`/data`), `APPSPORT_PUBLIC_DIR` (`/app/public`), `APPSPORT_CONTENT_DIR` (`/app/data`), `SW_KILL_SWITCH` (`1` = actif), `COACH_MODEL` (`claude-opus-5-5`), `ANTHROPIC_API_KEY` (lu, inutilisé au socle).
- **Image** : `ghcr.io/gnochance/appsport:vX.Y.Z`, base `node:24-slim`, contenu `server.mjs`, `public/` et `data/` sans `node_modules` ; utilisateur 1000 ; `read_only` avec `tmpfs /tmp` ; arrêt propre sur SIGTERM en moins de 10 s ; `mem_limit: 512m` ; port publié `127.0.0.1:3000:3000` seulement ; journaux JSON sur stdout sans corps, cookie, jeton, code, chaîne de requête, valeur C1 à C3 ni secret.
- **Garde de démarrage** : refus sans `/data/.appsport-volume` ou sans `/data/appsport.db`, sauf `init` ; jamais de base vide ; migrations au démarrage dans une transaction ; une migration inconnue `breaking` interdit le démarrage, des migrations inconnues non cassantes le permettent.
- **Exploitation** : instantanés quotidiens à 03:30 et avant chaque déploiement, 3 de chaque type dans `/data/snapshots/` (`daily-AAAAMMJJ.db`, `pre-vX.Y.Z.db`), aucun de plus de 30 jours ; base remplacée par une restauration gardée 30 jours dans `snapshots/replaced-<AAAAMMJJTHHMMSSZ>/` ; listes `data/ops/privacy-*.json` supprimées après `privacy:reapply` ; restic `local` (`/srv/backup/restic`) et `offsite` (B2, `appsport-backups`), `forget --keep-daily 30 --prune`, tags `daily` et `pre-deploy` ; timers `appsport-alive` toutes les 5 min, `appsport-backup` 03:30, `appsport-check` 04:00, `appsport-restore-test` le 1er dimanche du mois à 05:00 ; attente de `/api/health` de 2 min au plus ; séances `in_progress` de moins de 3 h affichées avant un déploiement ; **[décision plan]** Healthchecks `alive` 5 min (grâce 8 min), `backup` et `host` 24 h (2 h), `restore-test` 35 j (3 j) ; conteneur recréé à chaque maintenance mensuelle (journaux de 90 jours au plus, 03 §7) ; `appsport-update`, `appsport-backup` et `appsport-restore-test` exclusifs (`flock -n /run/appsport.lock`) ; recette sur iPhone et Android (`docs/exploitation/recette-telephones.md`, R-TST-4) avant le tag de toute version qui touche `src/sw`, la synchro, `local-db` ou un comportement iOS.
- **Tests** : TDD, dépendances injectées (`Clock`, `IdGen`, base), SQLite en mémoire, fake-indexeddb, aucun réseau externe. Interdits : `navigator.onLine` comme source de vérité, `Date.now()` ou `Math.random()` dans `packages/domain`, accès à Dexie depuis un écran (passer par `repos/`).
- **Hors périmètre du socle** : tables et écrans des briques 2 à 5, `data:export`, coach et `AiClient`, `data:validate`, `svg:check`, édition des réglages de charge (brique 3). Le socle livre les points d'extension : registre (`EntityRule.parent`, `c2Values`), hooks de synchro (`beforeApply`, `afterBatch`), `HEALTH_WITHDRAW_HOOKS` vide, taxonomie, `recommendTemplate` testé sur des modèles factices, catalogue vide servi par ETag, `SYNC_HOOKS` réduit à `sync_rejection`.
